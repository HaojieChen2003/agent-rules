# 数学任务工作流

## 1. 概念解释

1. 先给一句话钥匙句；
2. 给严格定义和适用范围；
3. 补充直觉并说明直觉不是定义；
4. 与容易混淆的概念比较；
5. 给正例、反例或边界例；
6. 给出可迁移的判断方法；
7. 只有用户要求训练时才加入自测。

## 2. 解题与解析推导

1. 写出目标形式或预期结论；
2. 明确条件、定义域、参数和符号约定；
3. 指出核心观察以及方法选择理由；
4. 展示关键推导并说明合法性；
5. 检查解集、参数区间、边界和退化情形；
6. 使用独立方式验证；
7. 总结可迁移的方法。

用户限制方法时遵守限制。替代解法只有在能提供新洞见、交叉验证或显著降低风险时才加入。

## 3. 证明

1. 规范化命题、量词和假设；
2. 识别直接证明、反证、归纳、构造、能量法、紧性或其他策略；
3. 列出依赖的定义和关键定理；
4. 完成逻辑链并说明关键合法性；
5. 检查边界、逆命题、存在性、唯一性与条件必要性；
6. 用低阶情形、反例搜索或独立方法复核。

证明纠错按 `rigor.md` 的“首个错误 → 最小修正”顺序执行，不先重写整篇证明。

## 4. 数学笔记

1. 确认 Markdown 或 LaTeX，以及速记、标准或深度模式；用户已明确载体时不重复提问。
2. 提取定义、核心结果、证明、反例、错误机制与依赖关系。
3. 完整读取 `note-design.md`，选择必要组件，不机械填满模板。
4. 写入项目时遵守项目目录、模板、宏和符号约定。
5. 检查公式、链接、层级、标签、引用和可检索性。

## 5. Python 验证与数值实验

1. 先写理论目标和可验证量；
2. 完整读取 `numerics.md`，选择依赖最少且能独立验证的方法；
3. 实现参考结果与待验证结果；
4. 运行正常、边界、低阶和敏感测试；
5. 报告绝对/相对误差、失败条件和复现信息；
6. 需要正式图形时遵守主框架的绘图选择规则；
7. 解释实验支持与不能支持的结论。

## 6. 数学内容写入 LaTeX

1. 先完成数学内容并通过内容验收；
2. 读取 `Latex排版助手.md`，检查入口文件、文档类、已有宏、标签和引用；
3. 使用适合的行内、无编号、编号或多行公式环境；
4. 只修改任务所需范围；
5. 按项目工具链编译；
6. 检查 PDF、未定义引用、标签、文献和版面警告；
7. 分别报告数学验证与 LaTeX 验收状态。

## 7. 混合任务

执行顺序通常为：

```text
数学内容 → 结构化笔记 → Python 或图形 → LaTeX 编译 → 统一验收
```

只加载主任务与至多两个辅助任务需要的规则，不加载无关的训练、论文或书库框架。
