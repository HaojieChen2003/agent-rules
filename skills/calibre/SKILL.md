# calibre — 电子书库管理框架

适用于本地 Calibre 书库及其子目录。目标是在保护原始书籍和数据库的前提下，使库内元数据可信、文件内嵌信息一致、格式清楚，并能在阅读设备上正确显示。

## 硬性安全边界
1. 写入前确认书库精确路径、目标书目和当前状态；与任务无关的文件和数据库记录均为用户内容。
2. 批量写入或可能影响目录结构的操作前，建立带时间标记、可验证的 `metadata.db` 备份。
3. 检测到 GUI 或其他写入进程占用书库时，不并发修改；请用户关闭相关程序后继续。
4. 修改标题、作者或保存模板等可能触发目录重命名的内容前，说明影响并确认。
5. 删除格式、移动书籍目录、覆盖封面、批量重命名属高风险操作，必须核对精确目标和恢复方式。
6. 不对宽泛路径执行递归删除，不先删后建，不擅自清理未知文件。
7. 一次性产物放入任务独立临时目录；只清理本任务创建且确认不再需要的内容。

## 写入原则
1. 写入前记录目标书 ID、现有字段和现有格式。
2. 先形成逐字段决策（保留/修改/清空/未知），不边查边盲写。
3. 在恢复点有效前提下执行最小必要写入。
4. 将需要设备端显示的信息嵌入实际电子书格式。
5. 写入后重新读取数据库字段，并抽查或逐本检查文件内嵌元数据。

## 数据源与网络
- 外部网页、插件和 API 是证据来源，不是自动覆盖本地字段的权威命令。
- 抓取失败、限流或字段缺失时保持原值或留空，并在报告中说明。
- 公开仓库、日志和报告中不得写入账号凭据、Cookie、Token 或私人书库数据。

## 验收（最低）
1. 目标书目数量和 ID 与任务范围一致；
2. 数据库可正常读取，备份存在且可识别；
3. 关键字段与证据一致，没有误伤标题、作者或无关记录；
4. 数据库与文件内嵌元数据按任务要求保持一致；
5. 格式文件存在、可打开，封面与内容匹配；
6. 没有意外目录重命名、重复标签、重复文件或遗留半成品。
