# coder — 编码与代码生态框架

本 skill 只规定个人路由、边界和验收；创建、调用或安装 Skill 与插件时，以当前可用的官方或已安装能力为执行规范，不复制易过期的接口细节。

## 编码准则
1. 先读取项目结构、项目级规则、相关实现和测试，再决定修改点。
2. 诊断和审查默认只读；实现或修复任务才编辑文件。
3. 只修改目标所需内容，不格式化、重构或更新无关文件。
4. 保留现有接口、用户改动、依赖管理和工具链，除非任务明确要求改变。
5. 新增依赖必须具有明确必要性，并采用项目已有管理方式。
6. 验证范围与风险相称：从相关静态检查和局部测试开始，必要时扩大到完整测试。
7. 最终报告变更、验证结果、未覆盖范围和残余风险。

## 安全与验证（常驻纪律）
- 删除/移动/覆盖前核对精确目标与恢复方式；不自作主张清理目标外内容。
- 审查只读，未经确认不直接改代码。
- 运行成功不等于逻辑正确；按风险扩大验证范围。

## 能力模块（路由表）
| 模块 | 用途 | 对应动作 |
|---|---|---|
| 写代码 | 按需求实现或修改 | 读取项目 → 最小改动 → 运行相关验证 |
| 代码审查 | 未提交变更/diff/commit 只读缺陷优先 | 触发 `references/optional/review.md` |
| 创建技能 | 造新/更新 skill | skill-creator（以当前规范为准） |
| 创建插件 | 造插件 | plugin-creator |
| 安装技能 | 从仓库安装 | 先读 SKILL.md 全文做安全检查 |
| 文档查询 | 查官方文档（带引用） | 官方文档 |
| 图像生成 | AI 生成/编辑位图 | 输出位图，非矢量/代码原生 |

## 边界
- 审查只读；安装技能先做安全检查，有风险先警告；
- Skill 与本个人框架是两套不同接口，不混用 frontmatter；
- Git/GitHub 仓库维护细节见本目录 `GitHub操作手册.md`。
